# Pay accuracy on internship postings

Generated by `python -m scripts.eval_pay` (from `api/`) on 2026-09-26.

**The question:** when a student opens an internship on Chronicle, is the pay shown the pay
the posting states?

**Ground truth:** `api/tests/fixtures/pay_eval/intern_pay_labeled.jsonl.gz` holds 120 internship
postings sampled from a recording of every active board taken on 2026-09-25:
- 55 companies, at most 4 postings per company.
- 70% of postings contain a money-like token; 30% don't.
- Each row keeps the raw ATS job object and a label for base pay: stated or not, min, max,
  currency, and period (hour/day/week/month/year, or "unclear" when a careful reader can't tell).
- The labels came from an annotator that never saw Chronicle's code, working from a written
  guide: equity, bonuses and stipends-for-X are not base pay, and a structured ATS pay block
  counts as part of the posting.
- 81 postings state pay (65 hourly, 8 yearly, 7 monthly, 1 unclear) and 39 don't.

**Scoring:**
- If a posting states no pay, the result is correct only when nothing is shown.
- If the period is unclear, the result is correct only when nothing is shown, because Chronicle
  never guesses a period.
- Otherwise the shown min, max, currency and period must all match the label.

"Before" is what Chronicle displayed prior to this change: `extract_salary` over the old
flattened text, with structured ATS pay ignored, always rendered as an annual "$Xk" figure.
"After" is the current ingest path: structured ATS pay first, then the text parser over
`plain_text` of the raw posting.

| measure | before | after |
|---|---|---|
| correct pay, postings that state pay (period clear) | 3/80 (3.8%) | 77/80 (96.2%) |
| correct pay, hourly postings | 0/65 (0.0%) | 62/65 (95.4%) |
| correct result, all postings (including correctly showing nothing) | 43/120 (35.8%) | 117/120 (97.5%) |
| pay invented on postings that state none | 0/39 | 0/39 |

**The three remaining misses:**
- A Toronto posting says "$30-$50 per hour" with no currency code. Chronicle shows it as
  written; the label records CAD, which it inferred from the location.
- Two PsiQuantum postings express pay as a rate table without currency symbols. Chronicle shows
  nothing rather than guessing.

**Honesty notes:**
- The "before" misses are not edge cases: every hourly rate was either dropped or multiplied
  by 1,000 into a fake annual salary.
- This set was not held out from development. Two general parser fixes came from inspecting
  "after" misses on it:
  - A wage line followed by a benefits bullet no longer inherits the bullet's "housing
    stipend" label, because blocks now end in a line break.
  - "$20/pay period … reimbursement" is no longer read as $20/hr.

  Before those fixes the "after" column read 73/80, 58/65 and 113/120. Treat the numbers above
  as a development-set result, not a blind one.
